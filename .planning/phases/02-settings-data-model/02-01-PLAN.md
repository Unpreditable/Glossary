Final state of src/main.ts:

```typescript
import { Plugin } from "obsidian";
import { GlossarySettings, DEFAULT_SETTINGS } from "./settings";

export default class GlossaryPlugin extends Plugin {
  settings!: GlossarySettings;

  async onload(): Promise<void> {
    await this.loadSettings();
    console.log("Smart Glossary loaded");
  }

  onunload(): void {
    // cleanup in future phases
  }

  async loadSettings(): Promise<void> {
    this.settings = Object.assign({}, DEFAULT_SETTINGS, await this.loadData());
  }

  async saveSettings(): Promise<void> {
    await this.saveData(this.settings);
  }
}
```

Critical constraints (locked by CONTEXT.md — do not deviate):
- `settings!: GlossarySettings` — the `!` definite assignment assertion is mandatory. Do NOT use `settings?: GlossarySettings` (spreads undefined checks everywhere) and do NOT initialize at declaration (would require a dummy value). The `!` is correct because loadSettings() is called before any code accesses this property.
- `await this.loadSettings()` must be the FIRST statement in onload(), before `console.log`.
- Merge strategy is exactly `Object.assign({}, DEFAULT_SETTINGS, await this.loadData())` — NOT spread syntax, NOT a library, NOT unwrapping loadData() before passing it. This handles the `null` return from loadData() on fresh install (null in position 3 is a no-op in Object.assign).
- `saveSettings()` contains ONLY `await this.saveData(this.settings)`. No side effects (addGlossaryStyles, buildGlossaryIndex) — those belong to Phases 6 and 3 respectively. Adding them here calls undefined methods.
- The import uses relative path `"./settings"` (no extension — tsconfig moduleResolution: bundler resolves this correctly).
